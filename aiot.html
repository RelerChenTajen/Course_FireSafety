1. 專題架構與硬體需求

本課程將帶領學生運用 Arduino 結合環境感測器，模擬火災發生時的數據變化，並透過 Node-RED 建立可視化儀表板。

Arduino Uno / Nano MQ-2 煙霧感測器 MQ-7 一氧化碳感測器 DHT22 溫溼度感測器（取代 DHT11） 蜂鳴器 (Buzzer) LED (紅/綠) + 220Ω 電阻 ×2

2. Arduino 核心程式碼

將此程式碼上傳至開發板（需安裝 Adafruit「DHT sensor library」）。程式會讀取感測器數值，在本地端控制蜂鳴器與 LED，並把數據格式化為 JSON 透過序列埠傳送。以 # 開頭的行是說明訊息，Node-RED 與網頁都會略過。

#include <DHT.h>

#define DHTPIN   2      // DHT22 溫溼度感測器
#define DHTTYPE  DHT22  // DHT11 只能量到 50°C，不適合火災偵測
#define MQ2_PIN  A0     // MQ-2 煙霧感測器（類比值 0~1023）
#define MQ7_PIN  A1     // MQ-7 一氧化碳感測器（類比值 0~1023）
#define BUZZER   8      // 蜂鳴器
#define LED_RED  9      // 紅色 LED：警報
#define LED_GRN  10     // 綠色 LED：正常

// 本地端（邊緣）警報門檻：與網頁模擬器預設值一致
const float TEMP_LIMIT  = 60.0;  // 定溫門檻 (°C)
const int   SMOKE_LIMIT = 400;   // 煙霧門檻（類比值）
const int   CO_LIMIT    = 300;   // CO 門檻（類比值）

DHT dht(DHTPIN, DHTTYPE);

void setup() {
  Serial.begin(9600);
  dht.begin();
  pinMode(BUZZER, OUTPUT);
  pinMode(LED_RED, OUTPUT);
  pinMode(LED_GRN, OUTPUT);

  // MQ 感測器需要預熱，數值穩定前不送出資料
  Serial.println("# MQ sensors warming up (20s)...");
  delay(20000);
}

void loop() {
  // 1. 讀取數據
  float temp  = dht.readTemperature();
  int   smoke = analogRead(MQ2_PIN);
  int   co    = analogRead(MQ7_PIN);

  // DHT 讀取失敗時跳過，避免送出 nan 造成 JSON 解析錯誤
  if (isnan(temp)) {
    Serial.println("# DHT read failed");
    delay(2000);
    return;
  }

  // 2. 本地端警報：網路或電腦斷線時仍能獨立發出警報
  bool alarm = (temp >= TEMP_LIMIT) || (smoke >= SMOKE_LIMIT) || (co >= CO_LIMIT);
  digitalWrite(BUZZER,  alarm ? HIGH : LOW);
  digitalWrite(LED_RED, alarm ? HIGH : LOW);
  digitalWrite(LED_GRN, alarm ? LOW  : HIGH);

  // 3. 傳送 JSON 給 Node-RED / 網頁
  //    格式: {"temp":28.5,"smoke":120,"co":60}
  Serial.print("{\"temp\":");  Serial.print(temp, 1);
  Serial.print(",\"smoke\":"); Serial.print(smoke);
  Serial.print(",\"co\":");    Serial.print(co);
  Serial.println("}");

  delay(2000);  // DHT22 取樣間隔至少 2 秒
}

Arduino 端只做簡單的固定門檻判斷（邊緣保底）；差動式計算與防誤報等較複雜的判定交給 Node-RED 或儀表板處理。

3. Node-RED 與 Dashboard 設定

在 Node-RED 中，我們需要建立「資料流」來接收 Arduino 的數據、進行判定並顯示。

  1. [Serial In]（node-red-node-serialport）：9600 baud，以 \n 分割訊息。
  2. [Switch]：略過以 # 開頭的說明行；再接 [JSON] 節點把字串轉為物件。
  3. [Function]：計算升溫速率並做交叉確認與持續時間判定（範例如下）。
  4. Dashboard 2.0（@flowfuse/node-red-dashboard）：
    • Gauge：顯示溫度、煙霧數值。
    • Chart：顯示趨勢；Text：顯示警報狀態。
    舊版 node-red-dashboard 已停止維護，新專題建議改用 Dashboard 2.0。
  5. Firebase：以 HTTP Request 節點呼叫 Realtime Database REST API（如 PUT …/fire/latest.json）寫入最新數據。
  6. 推播通知：LINE Notify 已於 2025 年 3 月 31 日終止服務，請改用 LINE Messaging API、Telegram Bot 或 Discord Webhook。

Function 節點範例：差動式 + 防誤報

// 輸入 msg.payload = {temp, smoke, co}
const d = msg.payload;
const now = Date.now() / 1000;

// 保留最近 30 秒的溫度，計算每分鐘升溫速率
let hist = context.get('hist') || [];
hist.push({ t: now, temp: d.temp });
hist = hist.filter(h => now - h.t <= 30);
context.set('hist', hist);
const span = now - hist[0].t;
const rate = span >= 5 ? (d.temp - hist[0].temp) / span * 60 : 0;

// 熱 / 煙霧 / CO 三項中至少兩項成立（交叉確認）
const heat = d.temp >= 60 || rate >= 10;
const hits = [heat, d.smoke >= 400, d.co >= 300].filter(Boolean).length;
const cond = hits >= 2;

// 條件需持續 10 秒才發報，過濾短暫干擾
let since = context.get('since') ?? null;
since = cond ? (since ?? now) : null;
context.set('since', since);

d.rate  = Number(rate.toFixed(1));
d.alarm = cond && (now - since) >= 10;
return msg;

4. 偵測器原理：定溫式、差動式與偵煙式

類型動作原理優點限制常見設置場所
定溫式 周圍溫度達到公稱作動溫度時動作 不受日常溫度起伏影響，誤報少 火勢擴大後才動作；對陰燃幾乎無效 廚房、鍋爐房、浴室等平時溫度變化劇烈的場所
差動式 溫度上升速率超過規定值時動作 對快速成長的火災反應早 開爐火、暖氣、日照等急遽升溫易誤報；對緩慢升溫反應差 一般居室、辦公室、倉庫
偵煙式 偵測空氣中的煙粒子 可在陰燃階段最早期發現 油煙、水蒸氣、粉塵易誤報 樓梯間、走廊、寢室、機房

實際探測器的種別、作動規格與設置位置，請依《各類場所消防安全設備設置標準》及產品認證規範。本專題的「多感測器交叉確認」則示範 AIoT 如何結合多種訊號來兼顧早期發現與降低誤報。

  2. 播放「廚房油鍋起火」：差動式比定溫式早幾秒動作？
  3. 播放「垃圾桶陰燃」：為什麼兩種熱偵測器都沒有動作？
  4. 改成「至少兩項交叉確認」再全部重播：誤報減少了嗎？偵測時間有什麼代價？
  5. 只調「持續秒數」：能消除哪一種誤報？為什麼對「暖爐熱氣」無效？

5. 實務注意事項

  • 溫度感測器：DHT11 量測範圍僅 0–50°C（誤差 ±2°C），永遠讀不到 60°C 的警報門檻；請改用 DHT22（−40–80°C，±0.5°C），並注意其取樣間隔需 ≥ 2 秒。需要量測更高溫度可改用熱電偶模組（如 MAX6675）。
  • MQ 系列氣體感測器：初次使用建議通電燒機 24–48 小時，之後每次開機也需預熱。讀值會受溫溼度影響，analogRead 得到的類比值只反映相對變化；要換算成 ppm 必須依 datasheet 的 Rs/R0 曲線校正。
  • MQ-7 加熱循環：datasheet 要求加熱器以 5V（60 秒）/ 1.4V（90 秒）交替運作，並在低電壓段結束前讀值。本專題直接以 5V 連續讀取，屬於簡化做法，數值僅供趨勢參考。
  • 邊緣保底：Arduino 本地端必須能獨立警報，不能只依賴網路與雲端。
  • 教學用途：本專題僅供教學示範，不能取代經認證的火警自動警報設備。
